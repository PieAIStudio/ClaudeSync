# Security and privacy

ClaudeSync manages local Desktop Code records and the current verified account’s cloud Code history. There are no analytics, ads, inference requests, custom backend or payment SDKs. Local management works offline; first-party profile/cloud calls are optional maintenance exceptions.

On macOS, identity uses an existing unexpired exact `user:profile` credential, one GET to Anthropic’s fixed profile origin, and account/organization checks. Keychain’s Claude Safe Storage decrypts the observed Desktop cache. A maintained N-API addon (`@napi-rs/keyring`) reads only that service asynchronously inside ClaudeSync, without a shared command-line client. Native errors are sanitized. Password buffers are wiped; the library's temporary JS strings cannot be securely zeroed and are immediately dereferenced. The prompt has no app-imposed deadline. Successful verification and whitelisted in-memory credentials are reused only for the unchanged Desktop login/cache snapshot in this app run; expiry is checked before session requests. Actual signed-app Keychain trust behavior remains manual acceptance, not a fixture-test claim. Cloud management separately selects an existing current-account/current-organization credential with `user:sessions:claude_code`; profile verification never falls back to that broader token. No token refresh, OAuth creation, device enrollment, cookies or secret persistence. Credentials remain in main-process memory, never in IPC, logs or backups; mutable decryption buffers are cleared. Switching/logout/cache changes discard pending results. Only verified UUID/email/organization bindings are remembered locally. CLI history never establishes the Desktop current login.

The verified organization determines the current local list and write scope. Other configured organizations cannot override current archive status. A different current organization does not prove a membership ended: absent explicit retirement evidence, other scopes remain unverified and old-copy cleanup cannot import or trash them. The current profile adapter does not create retirement evidence. Unknown accounts are not guessed or deleted. Automatic discovery changes only ClaudeSync configuration and preserves participation preferences.

Electron uses isolated sandboxed preload, typed IPC whitelist, main-frame checks, a strict CSP meta in the built file-page HTML, deny-by-default permission request/check handlers and restricted external navigation. Renderers cannot pass arbitrary file paths, bytes, credentials or API origins to mutation handlers.

Local writes require stopped Claude/Code processes, unchanged configuration, transcript fingerprints/inventory and complete index snapshots, an exclusive lock and final verification. Non-delete changes retain review, private byte backups and guarded recovery. Direct deletion has a short state-aware confirmation; no preview plan, deletion backup, journal, trash copy or recovery token. It removes only selected-group/account records, relevant archive hints and exclusive main JSONL bodies, using native deletion markers; it does not expand into hidden old copies. All login folders under the configured session root are checked for claims; shared content, projects, worktrees and auxiliary CLI files are retained. Unconfigured sibling claims can block removal. Interrupted deletion names transcripts already moved to the system Trash even if no index changed, without promising automatic undo. Existing backups from other operations are not silently purged.

Cloud writes consume the listed selection once, reverify account/organization, reread selected state, validate login/expiry before each fixed-origin DELETE, stop on failure and independently read back results. Uncertain outcomes are not retried. Only observed idle bridge records without task/template links are deletable; other records remain visible with a reason. No task-trigger/settings endpoint is called, and cloud actions do not edit Claude’s local database. The adapter is version-sensitive. Live reads were verified; real user deletions were not executed for acceptance.

Private settings, snapshots, backups and real-session screenshots must not be published in issues. Report vulnerabilities privately to the repository maintainer.
